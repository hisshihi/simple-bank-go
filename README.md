# simple-bank

Сервис банковских счетов и переводов на Go, построенный по **Clean Architecture** и **DDD**. Pet-проект, в котором я
отрабатываю проектирование доменной модели, транзакционные границы и конкурентный доступ к данным в PostgreSQL, а также
тестирование на всех слоях.

> Статус: **в разработке**. Доменная модель и перевод средств с транзакциями и блокировками готовы, сейчас пишутся тесты
> use case и HTTP API переводов. См. [Roadmap](#roadmap).

## Стек

- **Go 1.27.3**, `net/http` (`http.ServeMux` с методами и path-параметрами), `log/slog`
- **PostgreSQL 18**, **pgx/v5** + `pgxpool`, batch-вставки через `pgx.Batch`
- Транзакции: **[avito-tech/go-transaction-manager](https://github.com/avito-tech/go-transaction-manager)** (транзакция
  передаётся через `context`)
- Миграции **goose** (встраиваются в бинарь через `embed`)
- Тесты: **testify**, **mockery v3**, **testcontainers-go** (реальный PostgreSQL в Docker), `-race`
- **golangci-lint v2** (gofumpt, gci), **Taskfile**, **Docker Compose**
- Конфигурация через переменные окружения (`caarlos0/env`)

## Архитектура

```
cmd/simple_bank        точка входа
internal/
  domain/              доменная модель: сущности, value objects, инварианты (без зависимостей от инфраструктуры)
  usecase/             сценарии: оркестрация доменных объектов, репозиториев и транзакций
  repository/          доступ к PostgreSQL, маппинг record <-> domain
  handler/             HTTP-слой, DTO, единая обработка ошибок
  errs/                доменные ошибки
  app/                 DI-контейнер, запуск и graceful shutdown
  closer/              централизованное закрытие ресурсов
migrations/            SQL-миграции goose
```

Зависимости направлены внутрь: `handler → usecase → domain`, `repository → domain`. Интерфейсы репозиториев и
transaction manager объявлены **на стороне потребителя** (в пакете use case), поэтому use case зависит только от нужных
ему методов и тестируется на моках.

### Доменная модель

| Элемент    | Тип в DDD              | Что гарантирует                                                                                                                                         |
|------------|------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| `Money`    | Value Object           | Сумма в минимальных единицах (`int64`, копейки) + валюта. Иммутабелен: операции возвращают новое значение, смешивать валюты нельзя, уйти в минус нельзя |
| `Currency` | Value Object           | Только поддерживаемые валюты (RUB, USD, EUR и др.)                                                                                                      |
| `Account`  | Entity                 | Статусы `active / blocked / deleted`. `Withdraw` и `Deposit` работают только для активного счёта и не допускают отрицательного баланса                  |
| `Transfer` | **Aggregate Root**     | Создаётся сразу с двумя проводками (debit + credit), то есть двойная запись. Запрещены перевод на тот же счёт и нулевая сумма                           |
| `Entry`    | Entity внутри агрегата | Проводка по счёту. Конструктор приватный: Entry создаётся только через `Transfer` и сохраняется вместе с ним                                            |

На чём держится модель:

- **Деньги в `int64`, а не `float64`**, поэтому нет ошибок округления.
- **Поля приватные, наружу отдаются только геттеры.** `Transfer.Entries()` возвращает копию слайса, так что изменить
  агрегат снаружи нельзя.
- **Время инжектится через `Clock func() time.Time`**, поэтому доменная логика детерминирована в тестах.
- **Пара `New*` / `Restore*`**: `New` проверяет инварианты при создании, `Restore` поднимает объект из БД без повторной
  валидации.
- **UUID v7 в качестве первичных ключей**: они монотонны по времени, поэтому вставки идут в конец B-tree индекса без
  случайных page split, которые дают UUID v4.

### Перевод средств

```
txManager.Do(ctx, func(ctx) {
    lockPair(from, to)          SELECT ... FOR UPDATE в порядке возрастания ID
    from.Withdraw(money)        инварианты проверяет домен
    to.Deposit(money)
    NewTransfer(...)            агрегат + 2 проводки
    accountRepo.Save(from, to)
    transferRepo.Create(t)      перевод + проводки одним batch
})
```

- **Одна транзакция на весь перевод.** Репозитории получают текущую транзакцию из `context` через
  `CtxGetter.DefaultTrOrDB` и не знают о её границах. При любой ошибке всё откатывается.
- **Пессимистичная блокировка `FOR UPDATE`** защищает от lost update при параллельных списаниях с одного счёта.
- **Детерминированный порядок блокировок.** Счета блокируются по возрастанию ID, а не в порядке from → to. Иначе
  встречные переводы A→B и B→A захватывают строки крест-накрест и ловят `deadlock detected`.
- **Агрегат сохраняется целиком через репозиторий корня**: проводки пишутся в `transferRepo` одним `pgx.Batch`, то есть
  одним round-trip вместо N.

### База данных

- `CHECK (balance >= 0)` и `CHECK (direction IN ('debit','credit'))` дублируют доменные инварианты на уровне БД.
- Индексы под основные выборки: переводы по отправителю и получателю, проводки по счёту и по переводу.
- Мягкое удаление счетов через `deleted_at`.

## Тестирование

- **Домен**: table-driven unit-тесты на инварианты `Money`, `Currency`, `Account`, `Transfer`, `Entry`.
- **Use case**: unit-тесты на моках mockery v3.
- **Репозитории**: интеграционные тесты на настоящем PostgreSQL через testcontainers, миграции накатываются перед
  тестами.

```bash
task test          # go test -race ./...
task test:cover    # покрытие + coverage.html
task test:stress   # 100 прогонов, ловит флаки и гонки
```

Для интеграционных тестов нужен запущенный Docker.

## Запуск

```bash
cp .env.example .env
docker compose up -d     # PostgreSQL
task tools               # golangci-lint, goose в ./bin
task migrate:up
task run
```

`task` без аргументов запускает fmt, lint, test и build: это проверка перед пушем.

### API

| Метод  | Путь        | Описание                                                   |
|--------|-------------|------------------------------------------------------------|
| `POST` | `/create`   | Создать счёт. Тело: `{"name": "Denis", "currency": "RUB"}` |
| `GET`  | `/get/{id}` | Получить счёт по ID                                        |

```bash
curl -X POST localhost:8080/create -d '{"name":"Denis","currency":"RUB"}'
```
